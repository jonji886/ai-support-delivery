# ADR-0005：在 Agent 与 Tool 之间建立场景 Skill 层

原实现由 LangGraph 业务节点直接调用 Tool，能够完成流程，但“参数收集、Tool 权限、确认规则、降级条件和评测门禁”分散在编排代码中，能力难以被其他入口复用，也无法独立回答某个场景用了哪个版本。可选方案包括把每个 Tool 改名为 Skill、把完整流程继续留在 Agent，或建立独立的场景 Skill 层；本项目选择第三种：Agent 只负责选择 Skill，Skill 封装完成一类业务任务的规则与流程，Tool 只执行原子操作。

这一边界使 `return_resolution` 可以同时治理参数补齐、资格查询、用户确认、幂等提交和人工降级，而不是把两个退货 Tool 当成两个互不相关的“能力”。代价是增加 Manifest、Registry、Executor 和版本兼容成本，但换来可复用、可独立评测、可审计和可回滚的场景模块。运行时由 Skill Executor 强制检查 Tool 白名单与写操作确认；评测分成 Skill 选择和 Skill 执行两层，避免整体失败时无法区分“选错能力”还是“能力内部执行错误”。
