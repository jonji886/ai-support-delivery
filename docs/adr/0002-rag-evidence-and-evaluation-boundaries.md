# 将 RAG 召回、证据准入和效果验证分成独立边界

规则检索采用“生命周期硬过滤 → 候选召回/融合 → 证据充分性门禁 → 带原文片段引用”的顺序：过期版本不能靠排序降权处理，主题相关但不能直接支持问题的文档也不能生成确定性答案。评测同时固定开发集、回归集和挑战集，并对 lexical、vector、fusion、fusion+rerank 做消融；本地默认只启用已经证明有价值的 `fusion`，真实 reranker 接入后必须重新证明其准确率收益足以覆盖延迟、成本和故障面，才进入默认生产链路。

## Consequences

- 召回率不再等同于可回答率，报告分别记录召回、Top1、接受答案、无依据拒答和过期版本泄漏。
- 挑战集一旦被用于调参就不再是未见数据，必须降级为开发数据并补充新的挑战样本。
- 当前小语料上的 lexical 与 fusion 表现相同，测试 reranker 没有正向边际收益；保留 Provider 和消融能力，但不以组件数量替代效果证据。
