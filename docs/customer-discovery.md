# 客户调研与范围

## 当前客户假设

本项目没有真实客户数据，因此以下内容是立项前需要验证的客户假设，而不是对某个客户的事实描述。

目标客户是需要处理大量跨境售后咨询的电商团队，可能同时使用 OMS、物流查询、售后工单和规则/知识库。首期假设高频问题集中在物流查询、退货资格、退款进度和投诉升级。

## 需要验证的问题

- 最近 4 周售后会话量和问题类型分布是什么？
- 物流、退货资格、退款进度分别占多少比例？
- 当前人工平均处理时长、首次响应时延和一次解决率是多少？
- 客服需要在哪些系统之间切换？哪些字段最容易不一致？
- 哪些问题允许自动处理，哪些问题必须人工审批？
- 投诉、支付敏感和退款争议的错误成本如何估算？
- 客户的 OMS、物流、工单和知识库能否提供稳定接口及版本信息？
- 客户如何接受灰度、审计、回滚和人工接管？

## 场景选择

物流和退货资格是低风险、事实/规则相对明确、适合受控 Tool 的首期场景；投诉、退款争议和支付敏感问题用于验证风险识别与人工接管边界。真实客户系统、真实个人信息和真实退款不在本 POC 范围内。

## 交付验收重点

受控事实、规则引用、高风险转人工、可追踪日志、固定评测集和可复现部署。当前评测结果和未达标项以 [`poc-acceptance-report.md`](poc-acceptance-report.md) 为准。
